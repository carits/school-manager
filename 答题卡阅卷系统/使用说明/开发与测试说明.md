# 开发与测试说明

## 环境与启动

使用与项目依赖兼容的运行时，容器采用第22版运行时；原生扩展需要编译工具。全部命令在“答题卡阅卷系统”目录运行：

```bash
npm ci
npm run typecheck
npm run dev
```

前端开发代理指向本机 `5174`。前端路由基名为 `/answer-card`，如开发环境使用带此前缀的页面，反向代理也应将其接口转发至服务端，不能只开放静态文件。

## 构建

```bash
npm run build
npm run server
```

构建输出在自动生成的 `dist/`，不提交仓库。旧版独立入口需分别设置前端构建与服务端运行参数：

```bash
VITE_LEGACY_ONLY=1 npm run build
PROJECTX_LEGACY_ONLY=1 npm run server
```

这只是入口选择，数据库、端口、存储和代理仍应使用隔离配置。不要把上述命令直接用于正在阅卷的生产实例。

## 无真实数据的核心回归

```bash
node 脚本/verify-legacy-review-groups.cjs
node 脚本/verify-review-image-cache.cjs
node --experimental-vm-modules 脚本/verify-legacy-review-group-score.mjs
node 脚本/verify-legacy-paper-serials.cjs
```

以上覆盖临时数据下的分组、范围权限、零分、重复提交、汇总、图片缓存与流水号。其他数据库脚本执行前必须确认目标库和清理方式；带部署、迁移、生成、导入、恢复含义的脚本不应直接用于线上测试。

## 界面检查

管理员与普通教师分别验证：可见题块、身份隐藏、图片与流水号对应、评分成功、上一份/下一份、退出重进、已阅改分及手机滚动。界面测试使用专用测试考试，不修改真实教师评分。

## 目录变更检查

改目录后同时检查入口文件、构建脚本、静态资源路径、容器复制规则、识别器位置和说明链接。`package.json` 中的脚本命令仍作为统一入口，避免调用旧目录路径。
