# 现成答题卡扫描阅卷

## 本次实现范围

入口：管理员 / 学年主任进入已有考试的网上阅卷详情，选择「扫描阅卷」。先设置应考名单，再选择空白 PDF 保存模板。本次预置「2026年七年级第七周语文随堂练习」的几何区域：10 道客观题共22分，9个主观题评分单元共98分；第19题两个区域合成一个50分任务，总满分120分。预置仅含测量坐标，不包含第三方PDF及学生数据。

教师仍从原来的阅卷题目入口进入：现成答题卡自动使用只打分页面，输入完成后按回车保存，再领取下一份。没有必填理由、评语或标注。零分需要明确输入，空白和暂跳不算零分。支持按题目设定整数或半分、同题多人共享待批池、指定班级、释放、续领、本人最近30份已批回看改分。

## 使用顺序

1. 原有考试管理中建立考试并确认应考名单；扫描管理和分工需要管理员或学年主任权限。
2. 在「扫描阅卷」上传原始空白PDF，核对预设题号、总分及叠加区域。高级模板设置可导入/编辑JSON，更换题号、分值、考号位数、选项格和一个题目的多个作答区域。没有拖拽模板编辑器。
3. 先用少量实际扫描样本试识别。上传扫描PDF后，后台分批渲染、识别页型和方向，页面持续显示已处理进度。原始PDF不会在处理后删除。
4. 核对扫描顺序与考号，明确确认配对。支持正反相邻、先正后背同序、先正后背逆序；不完整或不确定的组合手动选页并绑定考号。确认前不产生学生成绩和教师任务。
5. 客观题标准答案可晚于扫描上传设置；第8题应明确两个正确选项及漏选分。默认漏选0分，错选/多选0分。未设置答案或不确定填涂保留空分，人工复核确认后才判分。
6. 选择每道主观题的教师与班级范围，保存分工。多人表示共同分摊，不代表双评。后续补扫按应考名单中的现有分工入池。更换应考名单后应重新保存分工。
7. 教师评分，管理者检查未完成项，从此入口导出当前成绩。所有题目完成后通过原有单场公布操作发布；外部答题卡不支持批量公布旁路。

## 配页边界

本卷第二页没有学生姓名或考号栏。自动识别只能确认页型，不能推断彻底打乱后的作文归属。推荐保留物理双面相邻顺序并关闭扫描仪自动删空白页。系统保留PDF原始页序，异常页不会过滤后顺移。批量确认仍要求上传者核对扫描顺序，并明确承担该批正反对应关系的确认；不能用算法置信度代替学生归属证据。

已确认第一页、尚缺作文页时，可先批第一页8题。补页须选择原答卷；不删除既有图片或评分。错误配给学生、同页重扫替换、整卷重组尚未提供管理界面：不要对归属有疑问的页面确认入库，先修正扫描顺序/考号。系统拒绝自动覆盖已有同考号答卷。

## 识别能力与限制

沿用 Linux 原生 OpenCV 识别器，新增独立 `--external` 模式。先尝试0/90/180/270度，使用四角实心定位标记校正，并用模板中稳定的印刷区域验证页型；然后在模板坐标中比较填涂，不进行全文OCR或AI主观评分。第三方二维码不参与外部模板身份绑定；原生成卡的二维码严格校验保持原样。

当前外部模式要求完整、清晰的四角定位标记与稳定印刷区域，不是任意无标记试卷识别器。严重裁边、缺标记、模糊、页型不确定时拒绝自动判分并提示重扫；没有无标记特征匹配和手动四点校正界面。坐标、阈值和实际扫描准确率必须用学校真实扫描样本验收，合成测试与空白模板不能替代该验收。

## 数据与并发约束

复用 `answer_cards`、`question_scores`、`student_scores`、`answer_block_crops`、`review_assignments` 和正式 `ReviewService` 评分入口；没有第二份正式成绩表。新增加的五张表仅保存冻结模板、持久化导入任务、扫描页、明确归属、幂等提交记录。

- 扫描任务落数据库：进程重启后可接管过期任务，已有页结果不重复执行。重复上传按考试与文件哈希去重。
- 同题多个区域在原生识别器/服务端按顺序拼图，只创建一个逻辑评分任务。
- 同场领卷、改派、人工确认与评分使用同一数据库命名锁；领取凭据、5分钟租期和评分轮次阻止过期覆盖。教师页面30秒续租，失败显示提示。重复提交采用请求编号与载荷摘要，换分数不能重复使用旧编号。
- SQLite 适配器增加单连接异步事务串行隔离，防止在渲染/文件等待期间交叉提交其他请求。MariaDB保持同连接GET_LOCK→事务→释放；不需要Redis。
- 同页补扫不删除已批任务；未批、缺页、待确认、缺答案均令正式总分为NULL，而不是0。单场公布在事务内再次检查完整性；改分自动撤回已发布成绩。导出从当前数据库读取，不读识别时的快照。
- 外部答题卡旧排版、旧导入、旧评分、旧分工写入口被保护，避免跳过模板冻结和幂等保存。原有生成卡流程不切换到外部模式。

## 部署与运维

没有自动部署或生产操作。合并/部署前备份数据库与整个 `ANSWER_CARD_DATA_DIR`。正常Compose构建会编译新增C++文件；仅更新Web而不重建原生识别器会报不支持 `--external`。数据库初始化以幂等DDL建立新增表；SQLite与MariaDB均需运行测试。

依赖沿用现有Node22、Poppler、Sharp、OpenCV C++与nlohmann-json。无云识别调用、GPU、额外模型服务或新消息队列。每个服务器进程一个扫描worker；采用持久化租约防止同批重复执行。单文件128MiB、500页，最多12个排队/处理中批次；每页长边上限5000像素，文件处理有超时与图像预算。存储可用空间不足1GiB时暂停渲染，释放空间后重试。

新增扫描原件和结果位于 `ANSWER_CARD_DATA_DIR/external-paper/`，必须纳入学校备份与归档；当前不会自动清除此目录。按考试人工归档需要先完成并核验成绩、保存原始PDF/数据库备份，再制定清理方式。缺考沿用原应考名单管理，不从扫描缺失推定缺考，也不自动记零分。

## 验证命令

```sh
npm ci
npm run typecheck
npm run build
npm run verify:external-paper
npm run verify:review-submit
npm run verify:permission-scope
npm run verify:block-total
ANSWER_CARD_RECOGNIZER_EXE=/absolute/path/to/fresh/answer-card-recognizer npm run verify:external-native
```

`verify:external-paper` 使用一次性临时SQLite库、合成空白PDF、合成题图和真实HTTP，不依赖生产数据。需要MariaDB时设置 `EXTERNAL_TEST_MARIADB=1`，只接受空的 `external_paper_ci` 数据库，测试结束必须销毁该数据库。`verify:external-native` 必须显式提供新编译的二进制，不会因缺少识别器而静默跳过。

验收重点：本卷22+98=120；作文只有一个任务；无标识背页不猜归属；旋转四方向；漏页不连锁错配；缺答案/未批总分不为0；共享池多人不会重复评分；零分、改分、断网重试；重启恢复；补页保留成绩；未授权读图失败；旧入口不可覆盖；修改后CSV和数据库一致。
